## 1. Оптимизация интерфейса под мобильный UI/UX. Что это означает?

Это адаптация интерфейса под условия использования на смартфоне: небольшой
экран, управление пальцем вместо мыши, нестабильное соединение и то, что
пользователь чаще смотрит на телефон одной рукой на ходу. На практике это
значит:

- размер тап-зон не меньше 44×44px (кнопки, ссылки, чекбоксы);
- крупный, легко читаемый текст без горизонтального скролла;
- минимум обязательных полей ввода, удобная клавиатура (`type="email"`,
  `type="tel"` и т.д.);
- важные действия — в зоне досягаемости большого пальца (обычно нижняя
  половина экрана), поэтому в проекте таб-бар вынесен вниз;
- отказ от hover-эффектов как единственного способа показать состояние
  (на тач-экране наведения нет);
- быстрая загрузка и лёгкие изображения, потому что мобильный интернет
  медленнее и дороже.

## 2. Каким образом можно устранить различия в мобильных браузерах?

- **CSS-reset / normalize.css** — приводит стили браузерных элементов
  (отступы у `body`, `ul`, `button` и т.д.) к единому виду. В проекте это
  `src/styles/reset.css`.
- **Автопрефиксы** (`autoprefixer` в связке со сборщиком) — добавляют
  вендорные префиксы (`-webkit-`, `-moz-`) для свойств, которые разные
  браузеры поддерживают по-разному.
- **Явные значения `box-sizing: border-box`** для всех элементов — иначе
  расчёт ширины с учётом padding/border отличается между браузерами.
- **Мета-тег viewport** — без него мобильные браузеры (особенно iOS Safari)
  масштабируют страницу под «десктопную» ширину ~980px.
- **Тестирование в DevTools / на реальных устройствах** (Safari на iOS
  особенно любит вести себя иначе, чем Chrome на Android).

## 3. Что означает стратегия Mobile First?

Это подход к вёрстке, при котором **базовые стили пишутся для самого узкого
экрана** (смартфона) без единого медиа-запроса, а затем через
`@media (min-width: …)` стили постепенно «достраиваются» под более широкие
экраны (планшет, десktop). Это противоположность старому подходу
"Desktop First", где сначала верстался широкий макет, а потом через
`max-width` стили обрезались/упрощались для мобильных.

Преимущества Mobile First:

- браузер телефона не загружает и не пересчитывает лишние desktop-стили;
- разработчик вынужден сразу думать о самом ограниченном случае (мало
  места, тач-управление), а не «дотягивать» его в конце;
- итоговый CSS обычно компактнее, потому что базовые правила — общие для
  всех экранов, а в `min-width`-блоках остаются только реальные отличия.

В этом проекте так и сделано: например, в `src/styles/auth.css` и
`src/styles/dashboard.css` базовые правила (без медиа-запроса) — это
макет под ~393px, а `@media (min-width: 48rem)` / `(min-width: 64rem)`
только переопределяют то, что действительно меняется на широком экране
(отступы, размер шрифта, sidebar вместо нижнего таб-бара).

## 4. Что такое медиа-запросы? Примеры

Медиа-запросы (`@media`) — это CSS-правило, которое применяет блок стилей
только при выполнении условия: ширина экрана, ориентация, плотность
пикселей, цветовая схема ОС и т.д. Позволяют одной кодовой базе HTML/CSS
адаптивно выглядеть на разных устройствах.

```css
@media (min-width: 48rem) {
  .sidebar { display: block; }
}

/* Стили только для экранов уже 480px (классический "мобильный" диапазон) */
@media (max-width: 30rem) {
  .hero__title { font-size: 1.5rem; }
}

/* Только для альбомной ориентации */
@media (orientation: landscape) { … }

/* Учитывает системную тёмную тему */
@media (prefers-color-scheme: dark) { … }
```

## 5. Что такое минификация файлов веб-страниц?

Минификация — это автоматическое сокращение размера файлов (HTML, CSS,
JS) перед публикацией: из кода убираются комментарии, лишние пробелы,
переносы строк, а имена переменных в JS могут заменяться на короткие.
Логика кода при этом не меняется — меняется только его «вес» в байтах,
из-за чего страница быстрее скачивается и парсится браузером.

В этом проекте минификация выполняется автоматически при сборке:

```bash
npm run build
```

`vite build` (см. `vite.config.js`) минифицирует JS через esbuild и
одновременно минифицирует CSS — готовые файлы попадают в `/dist`.
Как иллюстрация результата минификации CSS в проект также добавлена папка
`/dist-demo` с несжатой (`app.css`) и вручную минифицированной
(`app.min.css`) версией всех стилей проекта — 30 169 → 20 907 байт,
то есть файл стал примерно на 31% легче.
